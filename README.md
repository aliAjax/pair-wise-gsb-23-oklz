# hxwl-09 洁净室表面微生物擦拭采样与房间放行

换产品前凭表面微生物擦拭结果放行开工的电子看板，替代散落在微生物室的纸质单：按点位登记
消毒剂批次、培养基批次、菌落数与检验员；过期、漏采、超限的房间停在待处理；复擦换人并复测
全部点位，通过后冻结结果；改判只新增带原因的版本。

## 技术栈

React 19 + Vite + TypeScript + 纯 CSS（无 UI 组件库），localStorage 持久化。

## 本地运行

```bash
npm install
npm run dev          # http://localhost:5109
npm run typecheck    # 类型检查
npm run build        # 生产构建
npm run test:rules   # 判定层 31 项规则冒烟测试（纯函数，不依赖 DOM）
```

## 业务规则

- **按点位登记**：每个房间按洁净级别配置点位，一条记录含消毒剂批号、培养基批号、采样日期、菌落数(CFU/碟)、检验员。
- **同点位同批唯一**：同一房间同一点位在同一采样批次内只保留一条，重复登记为更新（upsert），不产生重复行。
- **限度（接触碟 Φ55mm）**：A 级 ≤0（标准 <1，不得检出）、B 级 ≤5、C 级 ≤25、D 级 ≤50 CFU/碟。
- **停在待处理（禁止开工）的条件**：
  - 消毒剂或培养基批次有效期早于采样基准日期；
  - 任一规定点位漏采，或已采样但菌落数未读数；
  - 任一点位菌落数超过本级别限度。
- **放行与冻结**：全部点位采全、读数、合格后，QA 判行放行，系统冻结该批次及其采样结果，看板进入「已放行」方可开工；停行同样冻结证据。
- **复擦**：对未通过批次另开复擦批次（必须填原因），须复测全部点位，且每个点位的检验员与源批不同；复擦仍不合格可继续复擦。
- **判定版本化**：判定记录只追加不覆盖。放行后的改判（撤销放行）必须填写原因并生成新版本，历史版本与判定时刻的问题快照保留可查。
- **下一轮换产**：已放行房间可开下一批采样，未放行房间只能走复擦，不能直接开新批。

## 分层结构

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 资料 | `src/data/` | 类型、级别限度、房间/点位/人员/批次主数据、种子记录 |
| 判定 | `src/domain/rules.ts` | 评估、唯一 upsert、放行/停行、冻结、复擦换人、版本追加（纯函数） |
| 保存 | `src/storage/repository.ts` | localStorage 读写、重置、JSON 导出（页面不直接碰存储） |
| 胶合 | `src/state/store.tsx` | React Context：把判定层动作接到保存层，统一错误提示 |
| 页面 | `src/ui/`、`src/App.tsx` | 放行看板（四列）、采样台账、资料维护、房间抽屉（登记/判定/复擦/版本） |

看板四列：**待采样 → 待处理 → 待放行 → 已放行**，只有「已放行」房间可开工。
